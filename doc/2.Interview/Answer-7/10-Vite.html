Vite 答案 ​

一、Vite 基础 ​

什么是 Vite？ ​

Vite 是基于原生 ESM的新型前端构建工具，由两部分组成：

  1. 开发服务器：利用浏览器原生 ES Module，按需编译，极速冷启动
  2. 生产构建：使用 Rollup 打包

二、Vite 为什么快？ ​

原因说明
原生 ESM开发时直接使用浏览器 ES Module import，不打包源码
ESBuild 预构建Go 语言编写，比 JS 快 10-100 倍
按需编译只编译浏览器请求的模块
HMR 极快ESM 自身就是热更新基础，无需重建整个 bundle
冷启动对比：
Webpack: 打包全部 → DevServer → 可用 (慢)
Vite: 启动 DevServer → 浏览器请求时按需编译 (快)

三、预构建（Pre-bundling / optimizeDeps） ​

Vite 启动时用 ESBuild 将 CommonJS/UMD 模块转为 ESM，并把有多个内部模块的包合并为一个，减少请求数。

javascript
// vite.config.js
export default {
  optimizeDeps: {
    include: ['lodash-es'],   // 强制预构建
    exclude: ['my-local-pkg'] // 排除
  }
};

四、HMR 热更新 ​

Vite 基于 ESM 实现 HMR：修改模块 → Vite 只失效该模块链 → 浏览器重新请求 →不刷新页面。

对比 Webpack：Webpack 需要重新构建受影响的 chunk，Vite 更轻量。

五、插件系统 ​

Vite 插件基于 Rollup 插件接口，兼容大部分 Rollup 插件，并提供 Vite 特有钩子。

javascript
// vite.config.js
import vue from '@vitejs/plugin-vue';
import react from '@vitejs/plugin-react';

export default {
  plugins: [vue(), react()]
};

六、构建与优化 ​

生产构建使用 Rollup，内置优化：

优化说明
CSS 代码分割按需注入，异步 chunk 的 CSS 自动提取
预加载指令<link rel="modulepreload"> 自动生成
异步 Chunk动态 import 自动分包
javascript
build: {
  target: 'es2015',             // 编译目标
  rollupOptions: {
    output: {
      manualChunks: { vendor: ['vue', 'vue-router'] }
    }
  },
  chunkSizeWarningLimit: 500,   // 分包警告阈值
  minify: 'terser'              // 或 'esbuild'（更快）
}

七、Vite vs Webpack 对比 ​

维度ViteWebpack
开发启动极快(ESM)慢（全量打包）
构建工具ESBuild(dev) + Rollup(prod)Webpack
HMR快（模块级）随项目增大变慢
配置复杂度低（约定）高
生态快速增长丰富成熟
SSR原生支持需配置
适用新项目复杂大型老项目

八、其他重要特性 ​

环境变量：.env 文件，import.meta.env.VITE_xxx 访问。

静态资源：直接 import，生产自动哈希 + 压缩。

javascript
import logo from './logo.png'; // → /assets/logo.abc123.png

// 代理
server: { proxy: { '/api': 'http://localhost:8080' } }

// SSR 支持
// Vite 提供完整的 SSR API：createSSRApp → renderToString
