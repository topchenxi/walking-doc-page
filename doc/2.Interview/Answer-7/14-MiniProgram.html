小程序 答案 ​

一、小程序基础架构 ​

小程序采用双线程模型：

渲染层(WebView) ← 数据绑定 → 逻辑层(JSCore/AppService)
         ↕ Native（JSBridge、网络、存储等）
  • 渲染层：WXML/WXSS 渲染界面（多个 WebView）
  • 逻辑层：JS 运行环境（一个 JSCore 线程），无 DOM/BOM
  • Native：系统能力桥接（相机、支付、蓝牙等）

二、生命周期 ​

App 生命周期 ​

onLaunch → onShow → (onHide → onShow)* → onError

页面生命周期 ​

onLoad → onShow → onReady → onHide → onUnload

组件生命周期 ​

created → attached → ready → moved → detached

三、数据绑定与事件 ​

javascript
Page({
  data: { message: 'Hello' },        // 数据
  updateMsg() {
    this.setData({ message: 'World' }); // 必须 setData 更新
  }
});
html
<view>{{message}}</view>
<button bindtap="updateMsg">更新</button>
<!-- catchtap 阻止冒泡；bindtap 允许冒泡 -->

setData 是异步的，频繁调用影响性能——应尽量合并。

四、组件化 ​

javascript
Component({
  properties: { title: { type: String, value: '' } },  // 外部传入
  data: { count: 0 },                                   // 内部数据
  methods: { increment() { this.setData({ count: this.data.count + 1 }); } },
  lifetimes: { attached() { /* 挂载 */ } }
});

slot 插槽：支持默认插槽和多 slot（需 multipleSlots: true）

五、API 能力 ​

分类API
网络wx.request, wx.uploadFile, wx.connectSocket
存储wx.setStorageSync, wx.getStorageSync（10MB 上限）
路由wx.navigateTo(保留), wx.redirectTo(关闭当前), wx.switchTab, wx.reLaunch
界面wx.showToast, wx.showModal, wx.showLoading
媒体wx.chooseImage, wx.previewImage, wx.getRecorderManager
位置wx.getLocation, wx.chooseLocation

六、性能优化 ​

  • 减少 setData 调用次数和数据量
  • 避免频繁的 DOM 操作（善用 wx:for 的 wx:key）
  • 图片懒加载 + WebP 格式
  • 分包加载（主包 < 2MB）
  • 预加载数据（onPreload / wx.preloadWebview）

七、跨平台开发 ​

方案特点
uni-appVue 语法，一套代码多端编译（微信/支付宝/百度/字节/H5）
TaroReact/Vue 语法，支持多端
原生开发性能最好，但需分别维护各平台代码

八、云开发 ​

微信云开发提供：云函数(Serverless)、云数据库(MongoDB)、云存储、云调用(免鉴权调用微信 API)。

javascript
// 云函数
exports.main = async (event) => {
  const db = cloud.database();
  return await db.collection('users').get();
};

九、WXS 脚本 ​

WXS 是运行在渲染层的脚本语言，可处理 WXML 数据（避免逻辑层→渲染层通信延迟）。主要用于过滤器、格式化等简单操作。

十、注意事项 ​

  • wx.request 最大并发 10 个
  • 页面栈最多 10 层
  • HTTPS 强制要求（开发可关）
  • web-view 组件：嵌入网页，需配置业务域名
