一、HTML 基础 ​

1. 什么是 HTML？它的基本结构是什么？ ​

问题：什么是 HTML？它的基本结构是什么？

答案：

HTML（HyperText Markup Language，超文本标记语言）是用于创建网页的标准标记语言。它不是一种编程语言，而是一种标记语言，通过一系列标签（tags）来描述网页的结构和内容。

HTML基本结构：

html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>页面标题</title>
</head>
<body>
    <!-- 页面内容 -->
</body>
</html>

结构说明：

  • <!DOCTYPE html>：声明文档类型为HTML5
  • <html>：根元素，包含lang属性指定语言
  • <head>：头部元素，包含元数据
  • <body>：主体元素，包含可见内容

补充说明：

  • HTML通过标签对内容进行语义化标记
  • 浏览器负责解析HTML并渲染成可视化页面

2. HTML 文档的标准组成部分有哪些？ ​

问题：HTML 文档的标准组成部分有哪些？

答案：

HTML文档的标准组成部分包括：

  1. 文档类型声明（Doctype）

    • 告诉浏览器使用哪种HTML规范
    • HTML5使用：<!DOCTYPE html>

  2. html根元素

    • 文档的根节点
    • 通常包含lang属性指定语言

  3. head头部元素

    • <meta charset="UTF-8">：字符编码
    • <meta name="viewport">：视口设置（响应式必需）
    • <title>：页面标题
    • <link>：引入外部资源（CSS、图标等）
    • <script>：引入JavaScript
    • <style>：内联样式

  4. body主体元素

    • <header>：页头
    • <nav>：导航
    • <main>：主要内容
    • <section>：章节
    • <article>：文章
    • <aside>：侧边栏
    • <footer>：页脚

补充说明：

  • 各部分语义化有助于SEO和可访问性

3. <!DOCTYPE> 的作用是什么？HTML5 标准 DOCTYPE 的意义是什么？ ​

问题：<!DOCTYPE> 的作用是什么？HTML5 标准 DOCTYPE 的意义是什么？

答案：

<!DOCTYPE>的作用：

  • 声明文档类型和DTD（文档类型定义）
  • 告知浏览器以哪种文档类型来解析文档
  • 影响浏览器的渲染模式（Quirks模式或Standards模式）

HTML5 DOCTYPE的意义：

html
<!DOCTYPE html>
  1. 简化声明：从复杂的长声明简化为简洁形式
  2. 统一标准：强制浏览器使用标准模式（Standards Mode）渲染
  3. 向前兼容：向下兼容HTML4.01和XHTML1.0
  4. 语义化：作为HTML5的标志性声明

补充说明：

  • 没有DOCTYPE会导致浏览器使用Quirks模式（兼容模式）
  • Quirks模式下会出现各种兼容性问题

4. Doctype 作用、Quirks 模式与 Standards 模式区别是什么？ ​

问题：Doctype 作用、Quirks 模式与 Standards 模式区别是什么？

答案：

Doctype作用：

  • 声明文档类型
  • 控制浏览器渲染模式

两种模式的区别：

特性Quirks模式（混杂模式）Standards模式（标准模式）
触发条件无Doctype或Doctype不正确正确的Doctype声明
盒模型IE盒模型（width含padding/border）标准盒模型（width仅含内容）
行内元素高度由内容决定由line-height决定
图片垂直对齐基线对齐底边对齐
表格继承字体样式不自动继承可继承font-size等
margin:auto不居中正常居中

代码示例：

html
<!-- 标准模式 -->
<!DOCTYPE html>

<!-- 混杂模式（不推荐） -->
<html>

<!-- HTML5之前的过渡模式 -->
<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Transitional//EN" "http://www.w3.org/TR/xhtml1/DTD/xhtml1-transitional.dtd">

补充说明：

  • 现代开发必须使用标准模式
  • 使用HTML5 Doctype是最简单的方式

二、HTML5 新特性与语义化 ​

5. HTML5 有哪些主要新特性？ ​

问题：HTML5 有哪些主要新特性？

答案：

HTML5的主要新特性包括：

  1. 语义化标签

    • <header>、<footer>、<nav>、<main>、<article>、<section>、<aside>
    • <figure>、<figcaption>、<time>、<mark>

  2. 表单增强

    • 新输入类型：email、url、tel、number、range、date、color等
    • 新表单属性：placeholder、required、pattern、autocomplete
    • <datalist>、<output>元素

  3. 音视频

    • <audio>、<video>原生支持
    • 媒体API：play()、pause()、currentTime等

  4. Canvas绘图

    • 2D绘图API
    • 支持动画、游戏开发、数据可视化

  5. 本地存储

    • localStorage：持久化存储
    • sessionStorage：会话级存储

  6. Web Worker

    • 后台线程，不阻塞UI

  7. WebSocket

    • 双向通信协议

  8. Geolocation API

    • 获取地理位置

  9. 拖放API

    • 原生拖放功能

  10. 离线应用

    • <manifest>、Service Worker

补充说明：

  • HTML5还包含大量API增强，如File API、Notification API等

7. 对 HTML 语义化的理解是什么？HTML 语义化的核心价值是什么？ ​

问题：对 HTML 语义化的理解是什么？HTML 语义化的核心价值是什么？

答案：

语义化理解：

  • 使用合适的标签表达内容的含义
  • 让机器（浏览器、搜索引擎）能够理解内容的结构

核心价值：

  1. SEO优化

    • 搜索引擎更好地理解页面结构
    • 提升关键词排名
    • 语义化标签提供更多元数据

  2. 可访问性（a11y）

    • 屏幕阅读器能正确解析内容
    • 帮助视障用户理解页面结构
    • ARIA属性配合使用效果更佳

  3. 代码可读性

    • 开发者易于理解代码结构
    • 便于维护和协作
    • 降低团队沟通成本

  4. 浏览器渲染

    • 浏览器能更准确地解析样式
    • 提升渲染性能
    • 样式化更精确

示例对比：

html
<!-- 非语义化 -->
<div class="header">
    <div class="nav">
        <div class="menu-item">首页</div>
    </div>
</div>

<!-- 语义化 -->
<header>
    <nav>
        <a href="/">首页</a>
    </nav>
</header>

补充说明：

  • 语义化是现代前端开发的基础要求
  • 不仅影响SEO，更关乎可访问性和用户体验

12. src 与 href 有什么区别？ ​

问题：src 与 href 有什么区别？

答案：

src和href的区别：

特性srchref
含义source（源）hypertext reference（超文本引用）
作用嵌入资源关联资源

具体区别：

  1. src属性
    • 用于引入资源到当前文档
    • 浏览器会立即加载并执行

html
<!-- 加载并执行脚本 -->

    • 建立当前文档与外部资源的链接

    • 不阻塞页面渲染
html

<link rel="stylesheet" href="style.css">

<a href="page.html">跳转</a>

<!-- 预关联 -->
<link rel="preconnect" href="https://example.com">

补充说明：

  • CSS用href，JS/图片用src

14. data-属性的作用是什么？如何使用？ ​

问题：data-属性的作用是什么？如何使用？

答案：

data-*属性作用：

  • 存储HTML元素的自定义数据
  • 在不污染业务逻辑的情况下传递数据
  • 便于JavaScript读取和操作

命名规范：

  • 以data-开头
  • 后面至少包含一个字符
  • 使用小写字母和连字符（kebab-case）
  • 避免使用大写字母
html
<!-- data-*属性示例 -->
<div id="user" data-user-id="12345" data-role="admin" data-permissions="read,write,delete">
    用户信息
</div>

JavaScript读取方式：

javascript
// 方式1：getAttribute（传统方式）
const element = document.getElementById('user');
const userId = element.getAttribute('data-user-id');
const role = element.getAttribute('data-role');

// 方式2：dataset API（推荐）
const element = document.getElementById('user');
const userId = element.dataset.userId;      // data-user-id → userId
const role = element.dataset.role;

// 设置值
element.dataset.permissions = 'read,write';

// 添加新属性
element.dataset.newAttr = 'value';

// 删除属性
delete element.dataset.role;

CSS中使用data属性：

css
/* 属性选择器 */
[data-role="admin"] {
    color: red;
}

/* 部分匹配 */
[data-permissions*="write"] {
    border: 1px solid blue;
}

补充说明：

  • data-*是HTML5标准
  • 适合存储简单数据，复杂数据用JSON.stringify
  • Vue/React中常用于组件通信

26. script 标签的 async 和 defer 属性有什么区别？ ​

问题：script 标签的 async 和 defer 属性有什么区别？

答案：

script加载方式对比：

方式加载执行阻塞DOM
普通script阻塞阻塞是
defer并行阻塞（DOM后）否
async并行立即否

执行时序图：

普通script：
HTML解析 → 暂停 → 下载script → 执行script → 继续解析

defer：
HTML解析（并行下载）→ HTML完成 → 执行script（按顺序）

async：
HTML解析（并行下载）→ HTML完成 → 执行script（下载完成即执行）

代码示例：

html
<!-- 普通script：阻塞渲染 -->
<script src="jquery.js"></script>

<!-- defer：延迟执行，顺序保证 -->
<script src="jquery.js" defer></script>
<script src="app.js" defer></script>  <!-- jquery.js先执行完再执行 -->

<!-- async：异步执行，不保证顺序 -->
<script src="jquery.js" async></script>
<script src="app.js" async></script>  <!-- 谁先下载完谁先执行 -->

<!-- 模块script：默认defer -->
<script type="module" src="app.js"></script>

使用建议：

javascript
// defer使用场景：依赖关系明确的脚本
// 执行顺序：按声明顺序
// 适用：主业务逻辑、框架

// async使用场景：独立脚本、无依赖
// 执行顺序：谁先加载完谁执行
// 适用：统计分析、广告、第三方SDK

// 普通script：首屏必需脚本
// 适用：关键依赖、样式初始化

  • async是HTML5添加的

27. 浏览器渲染原理是什么？ ​

问题：浏览器渲染原理是什么？

答案：

浏览器渲染流程：

1. HTML解析 → 2. DOM树构建 → 3. CSSOM构建 → 4. 渲染树 → 5. 布局 → 6. 绘制 → 7. 合成

详细步骤：

  1. 解析HTML

    • 浏览器接收HTML文档
    • 词法分析生成token
    • 解析tokens生成DOM节点

  2. 构建DOM树

    • 递归遍历所有节点
    • 构建文档对象模型
    • 遇到script会暂停（除非defer/async）

  3. 构建CSSOM

    • 解析CSS样式
    • 构建CSS对象模型
    • 处理CSS规则优先级

  4. 合成渲染树

    • DOM + CSSOM = 渲染树（Render Tree）
    • 只包含可见节点
    • 计算样式

  5. 布局（Layout）

    • 计算每个节点的位置和尺寸
    • 从根节点递归计算
    • 触发回流（reflow）

  6. 绘制（Paint）

    • 将渲染树绘制到多个图层
    • 填充颜色、边框等
    • 触发重绘（repaint）

  7. 合成（Composite）

    • 图层合并
    • GPU光栅化
    • 显示到屏幕

关键优化点：

javascript
// 减少回流
const element = document.getElementById('box');

// 不好：每次修改都触发回流
element.style.width = '100px';
element.style.height = '100px';

// 好：使用transform或合并修改
element.style.transform = 'translateX(100px)';

// 更好：使用CSS类
.element { transition: all 0.3s; }
element.classList.add('active');

// 减少重绘
// 使用opacity代替visibility
// 使用transform代替left/top

补充说明：

  • Chrome DevTools的Performance面板可查看渲染过程
  • 理解渲染原理有助于性能优化

29. CSS 为什么放在头部，JS 为什么放在底部？ ​

问题：CSS 为什么放在头部，JS 为什么放在底部？

答案：

CSS放head的原因：

  1. 避免FOUC（无样式内容闪烁）

    html
    <!-- 正确：CSS在前面 -->
<head>
    <link rel="stylesheet" href="style.css">
</head>
<body>
    <div class="content">内容</div>
</body>

<!-- 错误：CSS在body后，会先显示无样式内容 -->
<body>
    <div class="content">内容</div>
</body>
<link rel="stylesheet" href="style.css">

  2. CSSOM构建不阻塞DOM

    • CSSOM可以与DOM并行构建
    • 渲染树需要DOM + CSSOM同时完成

  3. 首屏渲染速度

    • CSS放head可以尽快开始构建渲染树
    • 用户更早看到样式内容

JS放底部的原因：

  1. JS阻塞HTML解析

    html
    <!-- JS会阻塞DOM构建 -->
<script>
    // 执行期间HTML停止解析
    document.write('test');
</script>

  2. JS可能操作DOM/CSSOM

    • JS执行时需要DOM和CSSOM
    • 放在底部确保DOM已经构建完成

  3. 允许CSS并行加载

    • JS放在底部不会阻止CSS加载
    • 提高页面加载速度

现代优化方式：

html
<!-- 使用defer/async -->
<head>
    <!-- defer：等HTML解析完按顺序执行 -->
    <script src="framework.js" defer></script>
    <!-- async：下载完立即执行 -->
    <script src="analytics.js" async></script>
</head>

<!-- 使用type="module"（默认defer） -->
<script type="module" src="app.js"></script>

<!-- 动态导入（按需加载） -->
<script>
    button.addEventListener('click', () => {
        import('./modal.js').then(module => {
            module.show();
        });
    });
</script>

补充说明：

  • 关键JS可以放head（如统计代码）
  • 首屏CSS必须放head

33. localStorage 的优缺点是什么？ ​

问题：localStorage 的优缺点是什么？

答案：

localStorage优点：

  1. 容量大

    • 约5MB存储空间
    • 可存储大量结构化数据

  2. 持久存储

    • 数据永不过期
    • 关闭浏览器后依然保留

  3. 简单易用

    • API简单直观
    • 同步操作，代码简洁

  4. 无需服务器通信

    • 不随HTTP请求发送
    • 减少网络开销

  5. 支持多种数据类型

    • 字符串
    • JSON序列化（对象、数组）

localStorage缺点：

  1. 只能存字符串

    • 需要JSON序列化
    • 复杂数据操作繁琐

  2. 同步操作

    • 大数据量会阻塞主线程
    • 移动端性能问题

  3. 安全性问题

    • 任何同源页面可访问
    • XSS攻击可窃取数据

  4. 无法存储敏感信息

    • 明文存储
    • 无加密机制

  5. 容量限制

    • 5MB对大型应用不足
    • 不同浏览器限制不同

  6. 无查询功能

    • 只能遍历所有key
    • 不支持索引查询

  7. 跨域限制

    • 严格同源策略
    • iframe嵌套受限

    • 避免永久存储风险
    http

    • 限制Cookie作用域
    http
    # 限制路径

# 限制域名（慎用）
Set-Cookie: token=xxx; Domain=example.com

42. 如何实现一个简易的路由？ ​

问题：如何实现一个简易的路由？

答案：

简易路由实现方案：

方案一：Hash路由

javascript
class HashRouter {
    constructor() {
        this.routes = {};
        this.currentHash = '';
        
        window.addEventListener('hashchange', () => this.handle());
    }
    
    // 注册路由
    register(path, callback) {
        this.routes[path] = callback;
    }
    
    // 处理路由变化
    handle() {
        this.currentHash = location.hash.slice(1) || '/';
        this.routes[this.currentHash]?.();
    }
    
    // 跳转
    push(path) {
        location.hash = path;
    }
    
    // 初始化
    init() {
        this.handle();
    }
}

// 使用
const router = new HashRouter();

router.register('/', () => console.log('首页'));
router.register('/about', () => console.log('关于'));
router.register('/user/:id', (id) => console.log('用户:', id));

router.init();

class HistoryRouter {

        this.handle();
    }
}

方案三：Vue Router风格

javascript
// 简单实现
const routes = [
    { path: '/', component: Home },
    { path: '/about', component: About },
    { path: '/user/:id', component: User }
];

const router = {
    install(Vue) {
        Vue.mixin({
            created() {
                if (this.$options.router) {
                    this._router = this.$options.router;
                }
            }
        });
        
        Object.defineProperty(Vue.prototype, '$router', {
            get() { return this._router; }
        });
        
        Vue.component('router-view', {
            render(h) {
                const { path } = location;
                const route = routes.find(r => matchPath(r.path, path));
                return route ? h(route.component) : null;
            }
        });
    }
};

function matchPath(pattern, path) {
    const params = {};
    const patternParts = pattern.split('/');
    const pathParts = path.split('/');
    
    if (patternParts.length !== pathParts.length) return false;
    
    for (let i = 0; i < patternParts.length; i++) {
        if (patternParts[i].startsWith(':')) {
            params[patternParts[i].slice(1)] = pathParts[i];
        } else if (patternParts[i] !== pathParts[i]) {
            return false;
        }
    }
    return true;
}

        '/user/:id': (id) => `<h1>用户ID: ${id}</h1>`
    };
    
    // 简易路由
    function router() {
        let path = location.pathname;
        
        // 匹配动态路由
        for (const [pattern, handler] of Object.entries(routes)) {
            const match = path.match(new RegExp('^' + pattern.replace(/:(\w+)/g, '(?<$1>\\w+)') + '$'));
            if (match) {
                const params = match.groups || {};
                const content = typeof handler === 'function' 
                    ? handler(params.id) 
                    : handler;
                document.getElementById('app').innerHTML = content;
                return;
            }
        }
        
        document.getElementById('app').innerHTML = '<h1>404</h1>';
    }

    document.addEventListener('click', (e) => {
        if (e.target.matches('a')) {
            e.preventDefault();
            history.pushState({}, '', e.target.href);
            router();
        }
    });
    
    window.addEventListener('popstate', router);
    router();
</script>
