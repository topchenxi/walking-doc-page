Git 答案 ​

一、Git 基础 ​

1. Git 与 SVN 的区别是什么？ ​

问题：Git 与 SVN 的区别是什么？

答案：

对比表格 ​

维度GitSVN
类型分布式版本控制集中式版本控制
存储方式每个开发者有完整仓库中央服务器存储
离线工作支持完整操作仅支持有限操作
分支管理轻量级，快速切换重量级，是目录拷贝
性能快（本地操作）慢（网络操作）
学习曲线较陡较平缓
适用场景开源项目、分布式团队小型团队、集中管理

2. Git 的基本工作流程是什么？ ​

问题：Git 的基本工作流程是什么？

答案：

四个区域 ​

工作区 → 暂存区 → 本地仓库 → 远程仓库
(Working) (Index) (Repository) (Remote)

常用命令 ​

bash
# 工作区 → 暂存区
git add <file>

# 暂存区 → 本地仓库
git commit -m "message"

# 本地仓库 → 远程仓库
git push origin main

# 远程仓库 → 本地仓库
git pull origin main

# 远程仓库 → 暂存区 → 工作区
git checkout <file>

二、分支管理 ​

3. Git 分支操作有哪些？ ​

问题：Git 分支操作有哪些？

答案：

常用命令 ​

bash
# 查看分支
git branch           # 本地分支
git branch -r        # 远程分支
git branch -a        # 所有分支

# 创建分支
git branch feature   # 创建分支
git checkout feature # 切换分支
git checkout -b feature  # 创建并切换

# 合并分支
git merge feature    # 合并 feature 到当前分支

# 删除分支
git branch -d feature   # 删除已合并的分支
git branch -D feature   # 强制删除

# 推送分支
git push origin feature

4. Git 合并方式有哪些？区别是什么？ ​

问题：Git 合并方式有哪些？区别是什么？

答案：

合并方式对比 ​

方式命令特点历史
Fast-Forwardgit merge快进合并，无 merge commit线性
No-FFgit merge --no-ff创建 merge commit保留分支历史
Rebasegit rebase变基，重写提交历史线性
Squashgit merge --squash压缩所有提交为一个简洁

代码示例 ​

bash
# Fast-Forward（默认）
git merge feature
# 如果主分支没有新提交，会快进到 feature 最新提交

# No-FF（保留分支信息）
git merge --no-ff feature
# 总是创建一个新的 merge commit

# Rebase（保持线性历史）
git rebase main
# 将 feature 的提交"移动"到 main 最新提交之后

Rebase vs Merge 对比 ​

维度MergeRebase
历史记录保留完整，有 merge commit线性，无 merge commit
安全性安全，不重写历史危险，重写历史
协作适合共享分支仅适合本地分支
可读性历史复杂历史清晰

工作流分支策略适用场景

四、Git 高级操作 ​

6. git reset、git revert、git checkout 的区别是什么？ ​

问题：git reset、git revert、git revert、git checkout 的区别是什么？

答案：

对比表格 ​

命令作用范围历史影响可恢复
git reset --soft移动 HEAD，保留暂存区和工作区删除提交记录可找回
git reset --mixed移动 HEAD，清空暂存区删除提交记录可找回
git reset --hard移动 HEAD，清空暂存区和工作区删除提交记录难找回
git revert创建新提交来撤销保留历史安全
git checkout切换分支/恢复文件不影响历史安全

代码示例 ​

bash
# reset --soft：撤销 commit，保留修改在暂存区
git reset --soft HEAD~1

# reset --mixed：撤销 commit 和 add（默认）
git reset --mixed HEAD~1

# reset --hard：撤销所有修改（危险！）
git reset --hard HEAD~1

# revert：创建新提交来撤销（安全，推荐用于已推送的提交）
git revert HEAD

# checkout：恢复文件到指定版本
git checkout HEAD -- file.txt

7. git stash 的使用场景是什么？ ​

问题：git stash 的使用场景是什么？

答案：

使用场景 ​

  • 需要切换分支但当前修改未提交时
  • 需要 pull 最新代码但本地有修改时

常用命令 ​

bash
# 保存当前修改
git stash
git stash save "work in progress"

# 查看 stash 列表
git stash list

# 应用并删除
git stash pop

# 应用但保留
git stash apply stash@{0}

# 删除 stash
git stash drop stash@{0}
git stash clear  # 清空所有

8. Git 如何解决冲突？ ​

问题：Git 如何解决冲突？

答案：

冲突产生场景 ​

  • 合并分支时同一文件被不同分支修改
  • rebase 时产生冲突
  • pull 时远程和本地有冲突

解决步骤 ​

bash
# 1. 查看冲突文件
git status

# 2. 手动编辑冲突文件，解决冲突标记
# <<<<<<< HEAD
# 当前分支的修改
# =======
# 其他分支的修改
# >>>>>>> feature

# 3. 标记已解决
git add <resolved-file>

# 4. 完成合并
git commit

五、Git 其他 ​

9. git pull 与 git fetch 的区别是什么？ ​

问题：git pull 与 git fetch 的区别是什么？

答案：

对比 ​

命令操作说明
git fetch下载远程更新，不合并安全，先查看再决定
git pull下载远程更新并合并= fetch + merge
bash
# fetch 后查看差异再决定
git fetch origin
git log HEAD..origin/main  # 查看远程新增的提交
git merge origin/main      # 手动合并

# pull 直接合并（可能产生冲突）
git pull origin main

10. Git 标签如何使用？ ​

问题：Git 标签如何使用？

答案：

标签类型 ​

类型命令说明
轻量标签git tag v1.0仅指向提交的指针
附注标签git tag -a v1.0 -m "release"包含完整信息

常用命令 ​

bash
# 创建标签
git tag v1.0.0
git tag -a v1.0.0 -m "Version 1.0.0"

# 查看标签
git tag
git tag -l "v1.*"

# 推送标签
git push origin v1.0.0
git push origin --tags

# 删除标签
git tag -d v1.0.0
git push origin --delete v1.0.0

补充说明：

Git 是版本控制的核心工具，面试重点考查：分支管理、合并方式、冲突解决、工作流。理解 reset/revert/checkout 的区别和 rebase vs merge 的选择是常考点。
