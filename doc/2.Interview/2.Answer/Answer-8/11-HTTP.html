HTTP 答案 ​

一、HTTP 协议基础 ​

1. HTTP 是什么？有什么特点？ ​

问题：HTTP 是什么？有什么特点？

答案：

核心定义 ​

HTTP（HyperText Transfer Protocol，超文本传输协议）是用于从 Web 服务器传输超文本到本地浏览器的应用层协议，基于 TCP/IP 协议通信。

特点 ​

  • 无状态：每次请求独立，服务器不保存客户端状态
  • 请求-响应模式：客户端发起请求，服务器返回响应
  • 基于 TCP：默认端口 80（HTTPS 为 443）
  • 简单快速：请求方法少（GET、POST 等），协议简单
  • 灵活：可传输任意类型数据（通过 Content-Type 指定）
  • 无连接：早期版本每次请求后断开（HTTP/1.1 支持持久连接）

2. HTTP 常见状态码有哪些？ ​

问题：HTTP 常见状态码有哪些？

答案：

状态码分类 ​

范围类别说明
1xx信息性请求已接收，继续处理
2xx成功请求已成功处理
3xx重定向需要进一步操作
4xx客户端错误请求有误
5xx服务器错误服务器处理出错

常见状态码 ​

状态码含义说明
200OK请求成功
201Created资源创建成功
204No Content成功但无返回内容
301Moved Permanently永久重定向
302Found临时重定向
304Not Modified资源未修改（使用缓存）
307Temporary Redirect临时重定向（保持请求方法）
400Bad Request请求语法错误
401Unauthorized未授权
403Forbidden禁止访问
404Not Found资源不存在
405Method Not Allowed请求方法不允许
500Internal Server Error服务器内部错误
502Bad Gateway网关错误
503Service Unavailable服务不可用
504Gateway Timeout网关超时

5. GET 和 POST 请求的区别是什么？ ​

问题：GET 和 POST 请求的区别是什么？

答案：

对比表格 ​

维度GETPOST
用途获取资源提交数据
参数位置URL 查询字符串请求体
数据长度受 URL 长度限制无限制
数据类型仅 ASCII任意类型
缓存可被缓存默认不缓存
书签可收藏为书签不可
安全性参数暴露在 URL相对安全（仍需 HTTPS）
幂等性幂等非幂等
后退/刷新无害会重新提交数据

使用建议 ​

javascript
// GET - 查询、搜索、获取数据
fetch('/api/users?id=1');

// POST - 创建、提交表单、上传文件
fetch('/api/users', {
  method: 'POST',
  body: JSON.stringify({ name: 'Alice' })
});

三、HTTP 版本演进 ​

6. HTTP/1.0 与 HTTP/1.1 的区别是什么？ ​

问题：HTTP/1.0 与 HTTP/1.1 的区别是什么？

答案：

对比表格 ​

维度HTTP/1.0HTTP/1.1
连接方式短连接（每次请求新建连接）持久连接（Keep-Alive）
管道机制不支持支持（队头阻塞）
缓存控制ExpiresCache-Control
Host 头非必需必需（支持虚拟主机）

7. HTTP/1.1 的缺点有哪些？ ​

问题：HTTP/1.1 的缺点有哪些？

答案：

主要缺点 ​

  1. 队头阻塞：同一连接中，后面的请求必须等前面的请求完成
  2. 队头阻塞：同一连接中，后面的请求必须等前面的请求完成
  3. 头部冗余：每次请求都携带大量重复头部信息
  4. 无优先级：无法指定资源加载优先级
  5. 多连接开销：为绕过限制需建立多个 TCP 连接

8. HTTP/2 有哪些新特性？ ​

问题：HTTP/2 有哪些新特性？

答案：

核心特性 ​

特性说明
多路复用一个连接上同时发送多个请求，解决队头阻塞
头部压缩使用 HPACK 算法压缩头部，减少传输量
服务器推送服务器主动推送资源到客户端
二进制分帧将报文拆分为二进制帧传输
请求优先级客户端可指定资源加载优先级
数据流每个请求/响应对应一个数据流

图示 ​

HTTP/1.1:
请求1 → 响应1
请求2 → 响应2  (串行)

HTTP/2:
请求1 ┐
请求2 ├→ 多路复用，并行传输
请求3 ┘

9. HTTP/3 有哪些改进？ ​

问题：HTTP/3 有哪些改进？

答案：

核心改进 ​

特性说明
基于 QUIC使用 UDP 而非 TCP
真正的多路复用解决 TCP 层面的队头阻塞
0-RTT 连接快速重连，减少延迟
改进的拥塞控制更好的网络适应
内置 TLS安全性内置于协议

HTTP/1.1 vs HTTP/2 vs HTTP/3 对比 ​

特性HTTP/1.1HTTP/2HTTP/3
传输层TCPTCPUDP (QUIC)
多路复用否是（应用层）是（传输层）
队头阻塞有有（TCP 层）无
连接建立3 次握手3 次握手+TLS0-RTT/1-RTT
头部压缩无HPACKQPACK

四、HTTP 缓存 ​

10. HTTP 缓存机制是什么？ ​

问题：HTTP 缓存机制是什么？强缓存与协商缓存的区别？

答案：

缓存类型 ​

类型机制状态码控制头
强缓存直接使用缓存，不请求服务器200 (from cache)Cache-Control, Expires
协商缓存请求服务器验证缓存是否有效304Last-Modified/If-Modified-Since, ETag/If-None-Match

缓存决策流程 ​

浏览器请求资源
    ↓
检查强缓存是否有效？
    ├── 是 → 直接使用缓存（200 from cache）
    └── 否 → 发送请求到服务器
              ↓
         检查协商缓存
              ├── 有效 → 返回 304，使用本地缓存
              └── 无效 → 返回 200 + 新资源

缓存控制头 ​

http
# 强缓存
Cache-Control: max-age=3600        # 缓存 1 小时
Cache-Control: no-cache            # 需要协商
Cache-Control: no-store            # 不缓存
Cache-Control: public              # 可被任何缓存
Cache-Control: private             # 仅浏览器缓存

# 协商缓存
Last-Modified: Wed, 21 Oct 2023 07:28:00 GMT
ETag: "33a64df551425fcc55e4d42a"

11. ETag 与 Last-Modified 的区别是什么？ ​

问题：ETag 与 Last-Modified 的区别是什么？

答案：

对比表格 ​

维度ETagLast-Modified
类型资源唯一标识（哈希值）最后修改时间
精度更高（内容变化即变化）秒级（1 秒内多次修改无法识别）
优先级更高（同时存在时优先使用）较低
性能服务器需计算哈希直接读取文件时间戳
适用场景内容变化频繁的资源静态资源

工作流程 ​

http
# 第一次请求
Request: GET /index.html
Response: 
  HTTP/1.1 200 OK
  ETag: "abc123"
  Last-Modified: Wed, 21 Oct 2023 07:28:00 GMT

# 后续请求（协商缓存）
Request:
  GET /index.html
  If-None-Match: "abc123"
  If-Modified-Since: Wed, 21 Oct 2023 07:28:00 GMT

Response:
  HTTP/1.1 304 Not Modified  # 资源未变化

问题：HTTP 与 HTTPS 的区别是什么？

答案：

对比表格 ​

维度HTTPHTTPS
全称HyperText Transfer ProtocolHTTP Secure

6. 数据传输

六、网络优化 ​

13. 从输入 URL 到页面显示发生了什么？ ​

问题：从输入 URL 到页面显示发生了什么？

答案：

完整流程 ​

1. DNS 解析
   URL → IP 地址
   浏览器缓存 → 系统缓存 → 路由器缓存 → ISP DNS

2. TCP 连接
   三次握手建立连接
   （HTTPS 还需 TLS 握手）

3. 发送 HTTP 请求
   浏览器构造请求报文发送

4. 服务器处理请求
   服务器返回响应

5. 浏览器渲染页面
   解析 HTML → 构建 DOM 树
   解析 CSS → 构建 CSSOM 树
   合并 DOM + CSSOM → Render Tree
   布局（Layout）→ 计算位置和大小
   绘制（Paint）→ 像素渲染
   合成（Composite）→ 显示

6. 断开连接
   四次挥手断开 TCP 连接

14. TCP 三次握手和四次挥手的过程是什么？ ​

问题：TCP 三次握手和四次挥手的过程是什么？

答案：

三次握手（建立连接） ​

客户端                    服务器
  |                          |
  |------ SYN=1, seq=x ----->|  1. 客户端发送 SYN
  |                          |
  |<----- SYN=1, ACK=1 ------|  2. 服务器回复 SYN+ACK
  |       seq=y, ack=x+1     |
  |                          |
  |------ ACK=1, seq=x+1 --->|  3. 客户端发送 ACK
  |       ack=y+1            |
  |                          |
  连接建立成功，可以传输数据

四次挥手（断开连接） ​

客户端                    服务器
  |                          |
  |------ FIN=1, seq=u ----->|  1. 客户端发送 FIN
  |                          |
  |<----- ACK=1, seq=v ------|  2. 服务器回复 ACK
  |       ack=u+1            |
  |                          |  服务器处理剩余数据
  |<----- FIN=1, ACK=1 ------|  3. 服务器发送 FIN
  |       seq=w, ack=u+1     |
  |                          |
  |------ ACK=1, seq=u+1 --->|  4. 客户端回复 ACK
  |       ack=w+1            |
  |                          |
  等待 2MSL 后关闭

为什么需要三次握手？ ​

  • 防止历史连接请求导致服务器误开连接
  • 双方确认彼此的收发能力正常
  • 同步初始序列号

15. 什么是跨域？如何解决跨域问题？ ​

问题：什么是跨域？如何解决跨域问题？

答案：

同源策略 ​

同源：协议、域名、端口都相同。任一不同即为跨域。

URL 1URL 2是否跨域原因
http://a.com/xhttp://a.com/y否同源
http://a.com/xhttps://a.com/y是协议不同
http://a.com/xhttp://b.com/y是域名不同
http://a.com:80/xhttp://a.com:8080/y是端口不同

解决方案 ​

方案说明适用场景
CORS服务端设置 Access-Control-Allow-Origin主流方案
JSONP利用 <script> 标签不受同源限制仅 GET
代理通过同域服务器转发请求开发环境
WebSocket不受同源策略限制长连接
postMessage跨窗口通信iframe

CORS 实现 ​

javascript
// 服务端设置响应头
res.setHeader('Access-Control-Allow-Origin', '*');
res.setHeader('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE');
res.setHeader('Access-Control-Allow-Headers', 'Content-Type, Authorization');

// 预检请求（复杂请求）
// 浏览器先发送 OPTIONS 请求，验证通过后再发实际请求
