一、Composition API（setup、ref、reactive） ​

1. 什么是 Composition API？与 Options API 的区别是什么？ ​

问题：什么是 Composition API？与 Options API 的区别是什么？

答案：

Composition API（组合式 API）是 Vue3 引入的一种全新的编写组件逻辑的方式。它通过函数式的 API 组合相关逻辑，替代了 Vue2 中基于选项配置（Options API）的写法。

核心区别：

对比维度Options APIComposition API
代码组织方式按选项分类（data、methods、computed 等）按逻辑功能组织
逻辑复用mixins（存在命名冲突、来源不清晰）自定义 Hooks/组合函数（来源清晰、类型推断友好）
TypeScript 支持较弱，类型推断困难优秀，天然支持类型推断
代码可读性大型组件中同一逻辑分散在不同选项相关逻辑聚合在一起
this 指向依赖 this，容易混淆不依赖 this，更直观

示例对比：

Options API 写法：

javascript
export default {
  data() {
    return {
      count: 0,
      user: null
    }
  },
  methods: {
    increment() {
      this.count++
    },
    async fetchUser() {
      this.user = await api.getUser()
    }
  },
  mounted() {
    this.fetchUser()
  }
}

Composition API 写法：

javascript
import { ref, onMounted } from 'vue'

export default {
  setup() {
    // 计数器逻辑
    const count = ref(0)
    const increment = () => count.value++

    // 用户数据逻辑
    const user = ref(null)
    const fetchUser = async () => {
      user.value = await api.getUser()
    }
    onMounted(fetchUser)

    return { count, increment, user, fetchUser }
  }
}

常见误区：

  • Composition API 并不是要完全替代 Options API，两者可以混合使用
  • Options API 在简单组件中仍然很适用
  • Composition API 更适合复杂组件和逻辑复用场景

2. setup 函数的作用是什么？它的执行时机是什么？ ​

问题：setup 函数的作用是什么？它的执行时机是什么？

答案：

setup 函数是 Composition API 的入口函数，是组件内使用 Composition API 的入口点。

核心作用：

  1. 作为组件的初始化入口
  2. 返回响应式数据和方法供模板使用
  3. 替代 data、methods 等选项的功能

执行时机：

  • setup 在组件实例创建之前执行
  • 在 beforeCreate 生命周期钩子之前执行
  • 在 created 生命周期钩子之前执行
  • 此时组件实例还未完全创建，因此无法访问 this
javascript
export default {
  // setup 在 beforeCreate 之前执行
  setup(props, context) {
    console.log('setup 执行')  // 第一个执行
    
    const count = ref(0)
    
    return { count }
  },
  beforeCreate() {
    console.log('beforeCreate 执行')  // setup 之后执行
  },
  created() {
    console.log('created 执行')  // 最后执行
  }
}

注意事项：

  • setup 函数是同步执行的
  • setup 执行时，props 已经解析完成
  • setup 中不能使用 this，因为此时组件实例尚未创建

3. setup 函数的参数有哪些？ ​

问题：setup 函数的参数有哪些？

答案：

setup 函数接收两个参数：props 和 context（上下文对象）。

第一个参数：props

  • 组件接收的 props 对象
  • 是响应式的，不能使用 ES6 解构（会失去响应性）
  • 可以使用 toRefs 进行解构

第二个参数：context

  • 普通的 JavaScript 对象，不是响应式的
  • 包含三个属性：
    • attrs：非响应式的属性对象（类似 Vue2 的 this.$attrs）
    • slots：非响应式的插槽对象（类似 Vue2 的 this.$slots）
    • emit：触发事件的方法（类似 Vue2 的 this.$emit）
javascript
export default {
  props: {
    title: String,
    count: Number
  },
  setup(props, context) {
    // props 是响应式的
    console.log(props.title)
    
    // context 的三个属性
    const { attrs, slots, emit } = context
    
    // 访问 attrs
    console.log(attrs.class)
    
    // 访问插槽
    console.log(slots.default)
    
    // 触发事件
    emit('update', 'new value')
    
    return {}
  }
}

注意事项：

  • props 不能直接解构，会失去响应性
  • context 可以安全解构，因为它是普通对象

4. setup 函数的返回值有什么要求？ ​

问题：setup 函数的返回值有什么要求？

答案：

setup 函数的返回值用于暴露给模板和其他组件选项使用。

返回值要求：

  1. 返回对象：对象中的属性可以在模板中直接使用
  2. 返回渲染函数：可以直接返回 h() 函数创建的虚拟 DOM
  3. 返回 undefined：不返回任何内容（较少使用）
javascript
import { ref, h } from 'vue'

export default {
  setup() {
    const count = ref(0)
    const name = 'Vue3'
    
    // 方式1：返回对象（最常用）
    return {
      count,
      name,
      increment: () => count.value++
    }
    
    // 方式2：返回渲染函数
    // return () => h('div', count.value)
  }
}

模板中使用：

vue
<template>
  <div>
    <p>{{ name }}</p>
    <p>{{ count }}</p>
    <button @click="increment">增加</button>
  </div>
</template>

注意事项：

  • 返回的 ref 在模板中会自动解包，不需要 .value
  • 不要返回非响应式的对象（会失去响应性）
  • 如果 setup 返回渲染函数，则不能有 template 模板
