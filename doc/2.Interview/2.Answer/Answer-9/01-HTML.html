HTML 答案 ​

一、HTML5 新特性与语义化标签 ​

1. 什么是 HTML？它的基本结构是什么？ ​

问题：什么是 HTML？它的基本结构是什么？

答案：

HTML（HyperText Markup Language，超文本标记语言）是构建网页的标准标记语言。它不是编程语言，而是通过标签描述网页内容的结构和语义。

核心要素：

  • 超文本：页面可包含图片、链接、音视频等非文本元素，通过超链接实现页面间跳转
  • 标记：使用 <标签名> 的形式对内容进行标注
  • 结构化：标签嵌套形成层级关系，构建 DOM 树

基本结构：

html
<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>页面标题</title>
  </head>
  <body>
    <h1>主标题</h1>
    <p>段落内容</p>
  </body>
</html>
部分说明
<!DOCTYPE html>文档类型声明，告诉浏览器使用 HTML5 标准模式渲染
<html>根元素，包裹整个页面，lang 属性指定语言
<head>元数据容器，包含字符编码、标题、样式、脚本引用等
<body>可见内容容器，所有展示给用户的内容放这里

2. HTML 文档的标准组成部分有哪些？ ​

问题：HTML 文档的标准组成部分有哪些？

答案：

一个完整的 HTML 文档由以下层次组成：

  1. 文档类型声明 <!DOCTYPE html>：声明使用 HTML5
  2. 根元素 <html>：所有元素的祖先
  3. 头部 <head>：包含元数据
    • <meta charset>：字符编码
    • <title>：页面标题
    • <meta name="viewport">：视口设置
    • <link>：外部资源引用
    • <style>：内嵌样式
    • <script>：脚本（可加 defer/async）
  4. 主体 <body>：页面可见内容

严格来说，文档结构可抽象为：Doctype → html → head + body 三层结构。

3. <!DOCTYPE> 的作用及 HTML5 意义是什么？ ​

问题：<!DOCTYPE> 的作用及 HTML5 意义是什么？

答案：

作用：告诉浏览器使用哪个 HTML 版本的标准来解析文档，防止浏览器进入怪异模式(Quirks Mode)。

HTML5 的 <!DOCTYPE html> 意义：

  • 简洁到极致，不再依赖 DTD（文档类型定义）
  • 自动触发标准模式(Standards Mode)，保证各浏览器行为一致
  • 向下兼容，旧浏览器也会尽量按标准模式处理

怪异模式 vs 标准模式：怪异模式下浏览器模拟旧版行为（如 IE5 的盒模型），导致布局差异。标准模式严格遵循 W3C 规范。

问题：HTML5 主要新特性有哪些？如何处理其浏览器兼容问题？

答案：

图形<canvas>, SVG 内联支持
存储localStorage, sessionStorage, IndexedDB

兼容处理：

问题：新增语义化标签及场景有哪些？

HTML5 新增的语义化标签让页面结构更加清晰：

标签含义使用场景

<time>时间/日期发布日期、活动时间
<mark>高亮文本搜索结果高亮

  <header>网站Logo和导航</header>

  <main>
    <article>

    </article>
    <aside>推荐文章</aside>
  </main>
  <footer>版权信息</footer>
</body>

9. 对 HTML 语义化的理解 ​

问题：对 HTML 语义化的理解

答案：

语义化就是用正确的标签表达正确的含义。它不仅是为了代码可读性，更是为了让浏览器、搜索引擎、辅助设备理解页面结构。

好处：

  1. SEO 友好：搜索引擎能准确抓取内容权重
  2. 可访问性：屏幕阅读器能正确解读页面结构
  3. 代码可维护性：开发者更容易理解和维护
  4. 移动端适配：结构化标签更利于响应式设计

反面例子：全用 <div> 和 <span> 堆砌页面——失去了结构语义，对机器和残障用户不友好。

10. HTML 语义化的核心价值是什么？ ​

问题：HTML 语义化的核心价值是什么？

答案：

核心价值概括为四个字：人机共读。

  • 对人：代码可读性强，团队协作高效
  • 对机器：
    • 搜索引擎爬虫准确理解内容层次 → SEO 排名提升
    • 屏幕阅读器能跳转到 <nav>, <main> → 无障碍体验
    • 浏览器阅读模式能提取 <article> 内容 → 用户体验提升

16. 说说你对 BOM 的理解，常见的 BOM 对象你了解哪些？ ​

问题：说说你对 BOM 的理解，常见的 BOM 对象你了解哪些？

答案：

BOM（Browser Object Model，浏览器对象模型）是浏览器提供的与页面内容无关的 API，核心是 window 对象。

BOM 对象作用
window顶层对象，全局作用域，所有 BOM 的入口
locationURL 信息，可跳转：location.href = 'xxx'
history浏览器历史记录：history.back(), history.pushState()
navigator浏览器和设备信息：navigator.userAgent, navigator.onLine
screen屏幕信息：screen.width, screen.height
localStorage / sessionStorage本地存储

BOM vs DOM：BOM 处理浏览器窗口和框架，DOM 处理文档内容和结构。document 本身就是 window.document。

17. mouseEnter 和 mouseOver 有什么区别？ ​

问题：mouseEnter 和 mouseOver 有什么区别？

答案：

对比维度mouseentermouseover
冒泡不冒泡冒泡
子元素触发进入子元素不触发进入子元素会触发
使用场景只需知道鼠标是否进入某区域需要精细控制每个子元素
javascript
// mouseenter: 进入父元素触发一次，进入子元素不触发
parent.addEventListener('mouseenter', () => console.log('进入父元素'));

// mouseover: 进入父元素触发，进入子元素也会再次触发（冒泡）
parent.addEventListener('mouseover', () => console.log('进入父或子元素'));

四、元数据与资源加载 ​

18. src 和 href 的区别是什么？ ​

问题：src 和 href 的区别是什么？

答案：

对比维度src (source)href (hypertext reference)
语义替换/嵌入当前元素引用/关联外部资源
加载行为阻塞式，暂停解析直到资源加载执行完毕非阻塞式，解析继续
典型元素<script>, <img>, <iframe>, <video><link>, <a>
浏览器处理暂停 HTML 解析，下载并执行并行下载，不暂停 HTML 解析

<script> 的 src 会阻塞解析，所以通常放在 </body> 前或加 async/defer。

五、SEO 优化相关标签 ​

19. SEO 优化注意事项有哪些？ ​

问题：SEO 优化注意事项有哪些？

答案：

HTML 层面：

  1. 语义化标签：用 <nav>, <article>, <header> 等替代 <div> 堆叠
  2. 标题层级：<h1> 唯一且含核心关键词 → <h2> → <h3> 逐级递减
  3. meta 标签：description 和 keywords
  4. 图片 alt：每张 <img> 添加准确的 alt 描述
  5. 结构化数据：使用 JSON-LD（Schema.org）标记
  6. URL 规范：使用 canonical 标签避免重复内容
  7. 页面速度：压缩资源、使用 CDN
  8. 移动友好：响应式设计，viewport 设置
html
<head>
  <title>核心关键词 - 品牌名</title>
  <meta name="description" content="150字以内的页面描述，含核心关键词">
  <link rel="canonical" href="https://example.com/article">
  <meta name="robots" content="index, follow">
</head>

20. 从 SEO 角度提出 HTML 书写注意事项（至少 2 条） ​

问题：从 SEO 角度提出 HTML 书写注意事项（至少 2 条）

答案：

  1. <h1> 唯一且含关键词：每个页面只有一个 <h1>，直接表达页面主旨
  2. <img> 必加 alt：爬虫通过 alt 理解图片内容
  3. <a> 使用描述性锚文本：避免 "点击这里"，改用 "查看 React 性能优化指南"
  4. <title> 前置关键词：核心关键词 - 次要关键词 - 品牌名
  5. meta description 具吸引力：虽不直接影响排名，但影响点击率(CTR)

六、无障碍访问（A11Y） ​

21. 无障碍化实现方法有哪些？ ​

问题：无障碍化实现方法有哪些？

答案：

  1. 语义化 HTML 是基础：<nav>, <main>, <button> 本身就带 ARIA 隐式角色
  2. ARIA 属性补充：当原生语义不够时使用
  3. 键盘可操作：所有交互元素可通过 Tab 键聚焦，Enter/Space 激活
  4. 色彩对比度：文本与背景对比度 ≥ 4.5:1（WCAG AA 标准）
  5. 表单标签关联：<label for="id"> 或直接包裹
  6. 图片 alt：装饰性图片用 alt=""，内容图片写描述
  7. 焦点管理：单页应用路由切换后主动将焦点移到主要内容区
html
<!-- ARIA 示例 -->
<button aria-label="关闭弹窗" aria-expanded="true">✕</button>

<div role="alert" aria-live="assertive">操作成功！</div>

<!-- 跳过导航链接 -->
<a href="#main-content" class="skip-link">跳到主要内容</a>
<main id="main-content" tabindex="-1">...</main>

22. 无障碍（A11Y）：缺少 ARIA 标签或键盘导航问题如何解决？ ​

问题：无障碍（A11Y）：缺少 ARIA 标签或键盘导航问题如何解决？

答案：

诊断步骤：

  1. 使用 Lighthouse / axe DevTools 扫描
  2. 手动 Tab 键遍历页面，检查焦点顺序和可见性

修复方案：

html
<!-- 问题：自定义下拉框无法键盘操作 -->
<!-- 修复：添加 tabindex, role, aria-*, 键盘事件 -->
<div class="custom-select"
     role="combobox"
     aria-expanded="false"
     aria-haspopup="listbox"
     tabindex="0"
     @keydown.enter="toggle"
     @keydown.escape="close">
</div>

<!-- 问题：图标按钮无文字说明 -->
<!-- 修复：aria-label -->
<button aria-label="删除项目">
  <span class="icon-delete"></span>
</button>

核心原则：能用原生 HTML 解决的不用 ARIA。<button> 天生可聚焦、可键盘激活，优于 <div onclick="...">。

七、HTML 基础元素 ​

23. 默认块级元素和行内元素有哪些？ ​

问题：默认块级元素（至少 3 个）和行内元素（至少 3 个）有哪些？

答案：

行内元素（不换行）：<span>, <a>, <strong>, <em>, <img>, <input>, <label>, <code>, <br>

24. 元素分类区别是什么？（行内元素、块级元素、空元素） ​

问题：元素分类区别是什么？（行内元素、块级元素、空元素）

答案：

类型特点举例
块级独占一行；可设宽高；宽度默认100%<div>, <p>, <h1>
行内不换行；宽高由内容决定；margin/padding 仅水平有效<span>, <a>
行内块 (inline-block)不换行但可设宽高<img>, <input>, <button>
空元素无闭合标签，无子节点<br>, <hr>, <img>, <input>, <meta>, <link>

31. 响应式设计原理是什么？ ​

问题：响应式设计原理是什么？

答案：

响应式设计的核心是一套代码适配多种设备，通过以下三个技术支柱实现：

  1. 流动布局：使用百分比、vw/vh、flex、grid 代替固定像素
  2. 弹性媒体：img { max-width: 100%; height: auto; } 图片随容器缩放
  3. 媒体查询：@media 在不同断点切换布局样式

设计理念："Mobile First"——先设计移动端，再通过媒体查询向大屏增强。

32. 渐进增强与优雅降级设计理念的区别是什么？ ​

问题：渐进增强与优雅降级设计理念的区别是什么？

答案：

维度渐进增强 (Progressive Enhancement)优雅降级 (Graceful Degradation)
起点从基础功能开始从完整功能开始
方向低端 → 高端，逐步增强高端 → 低端，逐步裁剪
关注点内容优先，功能是锦上添花体验优先，需保证降级可用
典型实践Mobile First 设计先做桌面版再适配移动端

推荐渐进增强：保证核心内容在任何设备可访问，新特性在不支持的浏览器中优雅失效而不是崩溃。

36. 多域名存储资源的优化原理是什么？ ​

问题：多域名存储资源的优化原理是什么？

答案：

核心是利用浏览器的同域名并发连接数限制（通常 6~8 个）。

策略：将静态资源分散到 2~4 个不同域名，增加并行下载数，加快页面加载。

40. 移动端视口：未设置 <meta name="viewport"> 导致缩放异常如何处理？ ​

问题：移动端视口：未设置 <meta name="viewport"> 导致缩放异常如何处理？

答案：

未设置 viewport 时，移动浏览器会以980px的默认视口宽度渲染，然后将页面缩小到屏幕宽度，导致文字极小。

解决方案：

html
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no">
属性作用
width=device-width视口宽度 = 设备宽度
initial-scale=1.0初始缩放 100%
maximum-scale=1.0禁止用户缩放（慎用，影响无障碍）

41. 表单验证：防抖处理或错误提示样式缺失如何解决？ ​

问题：表单验证：防抖处理或错误提示样式缺失如何解决？

答案：

防抖处理：避免每次按键都触发校验。

javascript
function debounce(fn, delay = 300) {
  let timer = null
  return function(...args) {
    clearTimeout(timer)
    timer = setTimeout(() => fn.apply(this, args), delay)
  }
}

input.addEventListener('input', debounce(function(e) {
  const value = e.target.value
  const isValid = /^[a-zA-Z0-9_-]{3,16}$/.test(value)
  // 切换错误样式
  e.target.classList.toggle('error', !isValid)
  // 显示/隐藏错误提示
  errorMsg.style.display = isValid ? 'none' : 'block'
}))

错误提示样式：

css
.input-error {
  border-color: #e74c3c;
  box-shadow: 0 0 0 2px rgba(231, 76, 60, 0.2);
}
.error-message {
  color: #e74c3c;
  font-size: 12px;
  margin-top: 4px;
}

42. SEO 不友好：SPA 未使用 SSR（如 Next.js）的解决方案 ​

问题：SEO 不友好：SPA 未使用 SSR（如 Next.js）的解决方案

答案：

SPA（Single Page Application）的 HTML 是空壳，内容靠 JS 动态生成，爬虫可能抓不到。

解决方案（按推荐程度排序）：

  1. SSR（服务端渲染）：Next.js (React), Nuxt.js (Vue) — 首选方案
  2. SSG（静态站点生成）：构建时预渲染为静态 HTML
  3. 预渲染：prerender-spa-plugin，构建时生成关键页面的 HTML
  4. 动态渲染：对爬虫返回预渲染版本，对用户返回 SPA
  5. 使用 react-helmet / vue-meta 管理 meta 标签

如果暂时无法迁移框架，至少确保 <title>, <meta description> 在服务端直出。

45. 从输入网址到页面显示的完整过程 ​

问题：从输入网址到页面显示的完整过程

答案：

1. URL 解析
   ├── 判断是 URL 还是搜索关键词
   └── 解析协议、域名、端口、路径

2. DNS 查询（逐级缓存）
   ├── 浏览器缓存 → OS hosts 文件 → 路由器缓存
   └── → ISP DNS → 根域名服务器 → 顶级域名 → 权威 DNS

3. TCP 三次握手
   ├── SYN →
   ├── ← SYN + ACK
   └── ACK →

4. TLS 握手（HTTPS）
   ├── Client Hello
   ├── Server Hello + 证书
   ├── 密钥交换
   └── 加密通道建立

5. 发送 HTTP 请求
   └── GET /index.html HTTP/1.1

6. 服务器处理并响应
   └── HTTP 响应（状态码 + 头部 + HTML 正文）

7. 浏览器解析渲染
   ├── 解析 HTML → DOM 树
   ├── 解析 CSS → CSSOM 树
   ├── DOM + CSSOM → Render 树
   ├── Layout（布局/回流）：计算位置和大小
   ├── Paint（绘制/重绘）：填充像素
   └── Composite（合成）：分层合并到屏幕

8. 四次挥手断开连接
   └── 或 Keep-Alive 复用连接

面试中强调：DNS 查询的缓存层级、TCP/TLS 握手、浏览器渲染的关键路径（DOM→CSSOM→Render Tree→Layout→Paint）。
